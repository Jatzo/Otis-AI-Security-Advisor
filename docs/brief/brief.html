A retrieval-augmented advisor for software vulnerabilities, measured honestly

Otis answers questions about vulnerabilities in 18 open-source packages from public advisory data, cites the records it used, declines when they say nothing, and has code check every claim. The project is as much about how to find out whether that works as about the system.

The problem

Developers need quick, correct answers about the packages they run. The public records disagree: GitHub and NVD put a different severity band on 46 of the 275 advisory and CVE pairs that both score.

The approach

  • Keyword search over 1,164 GitHub and NVD records and linked KEV entries, each with a header, top 10 to the model.
  • One model call that writes the answer and the claims it rests on.
  • A checker in plain code that refuses the whole reply if any claim is wrong or cannot be checked.
  • An evaluation fixed before the system existed, and a test split scored once from a tagged system.

What the measurement found

  • Retrieval is the limit, not the model.
  • The checker refused 9 right replies and withheld no wrong one. Its guarantee held, but there was nothing for it to catch.
  • A whole package in the prompt got 42 of 43 questions that name one, at twice the cost.
  • Nine retrieval variants were tried. Plain keyword search won, and embeddings did worse.

What the red team found

  • 56 attack cases and a held-out 56, on the unchanged system.
  • Instructions hidden in advisory text were followed in 1 case of 48.
  • A poisoned record can make a question unanswerable, and a false record with false ranges passes the checker by design.
  • No defence has been tested. The plan is written.
